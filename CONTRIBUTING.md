# Team Contribution Guide

## Before coding
1. Read the README and confirm the shared holiday data structure.
2. Pull the latest `main` branch.
3. Create a feature branch: `feature/short-description`.
4. Work on your assigned module unless the group leader agrees otherwise.

## Pull requests
1. Push your feature branch.
2. Open a Pull Request into `main`.
3. Explain what changed and how you tested it.
4. Request a review.
5. Merge only after the code has been checked.

## Code rules
- Use beginner-friendly Python covered by the course.
- Use meaningful variable and function names.
- Handle expected errors with appropriate `try/except` blocks.
- Validate user input before making API requests.
- Never commit API keys, passwords, or private information.
- Test your module before requesting a merge.

## Proposed allocation (10 members)
1. **Group leader:** coordination, integration, entry point, and progress tracking.
2. **API integration:** retrieve public holidays and handle HTTP/JSON errors.
3. **User interface:** Streamlit layout and user controls.
4. **Calendar display:** format, sort, filter, and display holiday records.
5. **Cultural awareness:** researched explanations, greetings, and customs.
6. **Country comparison:** compare two countries' dates and celebrations.
7. **File handling:** save/load favourites, guides, and comparison results.
8. **Regex and validation:** validate country codes and year input.
9. **OOP:** design shared data classes and service classes with module owners.
10. **Testing and documentation:** test cases, bug reports, README updates, and presentation support.

Every member must contribute a technical deliverable, test their work, and be ready to explain it during the presentation.
